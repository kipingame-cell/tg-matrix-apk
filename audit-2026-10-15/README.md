## Замечания и порядок исправления

P0 — критический риск; P1 — высокая важность; P2 — существенное улучшение. Приоритеты — оценка аудита, не CVSS.

### TG-MATRIX-APK-01 · P1 · Имена участников вставляются в HTML без экранирования

- Статус: Подтверждено чтением кода.
- Место: `www/heatmap/app.js:28`; [открыть файл](https://github.com/kipingame-cell/tg-matrix-apk/blob/main/www/heatmap/app.js). Номер строки относится к проверенному снимку.
- Проблема и последствия: Значение u используется внутри HTML и атрибута value. Контролируемое имя/импорт может изменить разметку и создать DOM XSS. В APK это особенно опасно рядом с localStorage-сессией.
- Исправление: Строить input/span через DOM, текст задавать textContent; исключить HTML-конкатенацию внешних данных.
- Критерий приёмки: Имя с кавычками и HTML отображается буквальным текстом и не создаёт дополнительные элементы.

### TG-MATRIX-APK-02 · P0 · Ключ подписи и пароль доступны в публичном исходнике

- Статус: Подтверждено кодом и деревом; ключ не декодировался.
- Место: `apply-signing.js:18`; [открыть файл](https://github.com/kipingame-cell/tg-matrix-apk/blob/main/apply-signing.js). Номер строки относится к проверенному снимку.
- Проблема и последствия: Дерево содержит tgk.keystore.b64, а сборочный скрипт — данные для использования ключа. Секретность подписи потеряна для всех читателей публичного repo.
- Исправление: Подготовить план миграции подписи с учётом обновлений установленных APK; хранить production-ключ отдельно. Простое удаление файла не отменяет опубликованные копии.
- Критерий приёмки: В production pipeline нет ключа в Git, подтверждена цепочка обновления со старой версии.

### TG-MATRIX-APK-03 · P1 · Telegram-сессия и API-ключи доступны JavaScript через localStorage

- Статус: Подтверждено чтением кода.
- Место: `src/app.js:60`; [открыть файл](https://github.com/kipingame-cell/tg-matrix-apk/blob/main/src/app.js). Номер строки относится к проверенному снимку.
- Проблема и последствия: Любое выполнение чужого JS в origin получает долговременную сессию. Наличие неэкранированных HTML-путей увеличивает риск.
- Исправление: Изолировать секреты в нативном защищённом хранилище, сузить JS bridge и устранить DOM-инъекции.
- Критерий приёмки: Выход удаляет все секреты; импортированный контент не получает доступ к session.
